# 大型教材のファイル構成ルール Ver.1.0

## RULE-APP-STRUCTURE-001

**大型教材は複数ファイル構成を標準とする。**

このルールは、今後作成する次のような教材へ共通して適用する。

- 結晶構造シミュレーター
- 力学シミュレーター
- 分子構造シミュレーター
- 3D表示を含む教材
- 描画・計算・状態管理が複雑な教材

## 標準構成

```text
<app-id>/
├─ index.html
├─ app.manifest.json
├─ css/
│  └─ app.css
├─ js/
│  ├─ app.js
│  ├─ model.js
│  ├─ renderer.js
│  └─ ui.js
├─ data/
│  └─ settings.json
├─ assets/
└─ README.md
```

## 適用判断

次のいずれかに該当する新規教材は、原則として複数ファイル構成にする。

- Simulation、3D、Canvas、WebGLを主要機能とする
- 計算Model、描画、UI、Dataの責任分離が必要
- 1ファイルでの保守が困難になる規模
- 複数人または複数AIによる継続改修を予定する

小規模な計算練習や単純な可視化教材は、1ファイル構成を選択できる。

既存の1ファイル教材は直ちに分割しない。大規模改修時に移行を検討する。

## 運用上の適用

新規教材の登録は、原則として教材追加ウィザードを使用する。
大型教材を手作業またはAIが直接追加する場合も、本ルールに従って複数ファイル構成にする。
既存教材との互換性を保つため、現段階では`structureMode`をManifest Schemaの必須Fieldにはしない。
CIによる一律強制は、既存教材の移行方針を確定した後に検討する。
